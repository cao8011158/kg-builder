# Manual entity resolution v0.1

Status: **review evidence, not a frozen cross-paper ontology**. This offline layer records explicit Method, ResearchProblem and Artifact identity decisions. It does not rewrite extractions, promote Draft status, claim scientific truth, or automatically merge by name/title similarity.

The packaged [`entity_resolution_v0_1.json`](../src/kg_builder/schemas/entity_resolution_v0_1.json) is the executable JSON Schema 2020-12 manifest profile. A manifest declares `schema_version: research-kg-entity-resolution/0.1`, `batch_id`, `reviewer`, `reviewed_at`, `source_db_sha256` (provenance), optional `notes`, `entities[]`, and `mentions[]`. Only this declared version is accepted. The `source_db_sha256` records the reviewed database snapshot; the import pins each used extraction by its exact stored `payload_json` SHA256, so a later database change is detected even when the file hash changes for unrelated reasons.

An entity has `entity_id`, `kind`, `name`, `scope` (`named_concept` or `paper_version_local`), `scope_version_id` (NULL for named, owning version for local), `aliases`, `identity_definition`, and nonempty `support[]`. An Artifact additionally has `artifact_kind`. Each support cites `extraction_id`, exact `source_payload_sha256`, and either `evidence_ref` or `/evidence_locators/N` pointer. A mention identifies one `/methods/N`, `/research_problems/N`, or `/artifacts/N` source item by `extraction_id`, `kind`, path, exact payload hash, source name/key, `decision`, nullable `entity_id`, rationale, and evidence refs/pointers. `pending` has a NULL entity; `resolved` has a matching-kind entity and at least one valid evidence anchor. Artifact subtype must also match the source `artifact_kind`. Local entities must belong to the source version. A source Artifact marked `paper_version_local_configuration` or `annotator_descriptive` cannot resolve to a global named concept.

Run `python scripts/import_entity_resolution.py --input private-manifest.json --db private.sqlite3` after installing project dependencies. The CLI validates the complete JSON schema before opening SQLite, then validates every source identity/hash/evidence pointer before writing. `import_resolution_manifest(connection, manifest, raw_json=None)` writes one atomic savepoint and leaves an outer caller transaction under caller control. Batch IDs are immutable: a semantic exact repeat returns unchanged data; a changed manifest with the same ID raises. The original first-import document bytes are retained in `entity_resolution_batches.payload_json` and the canonical document digest in `manifest_sha256`.

Use `get_resolution_mentions(connection, batch_id, extraction_id)` to inspect one explicit review. It returns historical decisions plus `stale` and an entity only when both the mention and **every supporting extraction** still match pinned payload hashes in one SQLite read snapshot. A stale decision is retained, but its entity is hidden. The query uses the composite mention key, composite entity key, and extraction primary keys; it does not select an implicit latest batch or scan the registry. A missing review returns without reading extraction payloads. Otherwise full extraction payloads are read only for the requested mention and its support closure to verify exact bytes. An existing caller transaction remains caller-owned.

The offline reconciler retains all three resolution tables and original audit rows when source extraction IDs and payload bytes remain identical. If a canonical paper/version/extraction mapping would change any annotated source binding or payload bytes, reconciliation fails and leaves the inputs untouched. Unknown tables/columns and contradictory immutable batch rows also fail rather than discarding review evidence. The manifests and databases are private data and must remain outside the public repository.
